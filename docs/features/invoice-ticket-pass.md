# 🎫 Invoice & Ticket Pass Generation

## Overview

EventZen automatically generates **professional PDF assets** for every successful booking:

- **Ticket Passes** - generated by the .NET Ticketing Service; a premium, styled PDF containing the event details, ticket serial number, attendee name, and a scannable QR code
- **Payment Invoices** - generated by the Java Finance Service; an HTML-to-PDF invoice with itemized payment details, stored in MinIO and linked to the payment record

Both assets are stored in **MinIO object storage** and can be downloaded or emailed to the user.

---

## Ticket Pass Generation (.NET Ticketing Service)

```
Booking confirmed (TicketingService)
         │
         ▼
TicketDeliveryAssetService.BuildConfirmationEmailHtml()
         │   Inlines: event title, time, venue, ticket type,
         │             ticket serial, registration ID
         ▼
TicketDeliveryAssetService.BuildTicketPassPdf()
         │   Calls QrCodeService.Generate() → SVG QR code
         │   Embeds QR code as data URI in PDF template
         ▼
TicketPassStorageService.UploadAsync()
         │   Uploads PDF to MinIO bucket
         │   Returns object key + presigned URL
         ▼
URL returned to TicketingService → stored on RegistrationDocument
```

### Ticket Pass Contents

| Field | Value |
|---|---|
| Event name | From booking |
| Date & time | Formatted with timezone |
| Venue | Name + city |
| Ticket type | e.g. "VIP", "General Admission" |
| Ticket serial | Human-readable short code (e.g. `EVT-2026-0042`) |
| QR code | Signed payload: `{ticketId}\|{registrationId}\|{eventId}.{hmac}` |
| Attendee name | From user profile |

## Invoice Generation (Java Finance Service)

```
Payment captured (SUCCEEDED status)
         │
         ▼
InvoiceAssetService.uploadInvoice(payment)
         │   buildInvoiceNumber()  →  "INV-2026-0001"
         │   buildInvoicePdf()     →  HTML-rendered PDF bytes
         │   ensureBucketExists()  →  MinIO bucket auto-created
         │   minioClient.putObject() → stored as "invoices/{year}/{uuid}.pdf"
         ▼
Returns StoredInvoice { invoiceNumber, objectKey, publicUrl }
```

### Invoice Contents

| Field | Value |
|---|---|
| Invoice number | Sequential `INV-{year}-{seq}` |
| Payment date | ISO formatted |
| Event name | From payment record |
| Ticket type | From payment record |
| Amount | Formatted with currency |
| Razorpay order ID | For reconciliation |
| Payer name | From payment record |

## Key Source Files

| File | Service | Purpose |
|---|---|---|
| `TicketDeliveryAssetService.cs` | Ticketing (.NET) | Builds HTML email + PDF pass template |
| `TicketPassStorageService.cs` | Ticketing (.NET) | Uploads PDF to MinIO via S3-compatible API |
| `QrCodeService.cs` | Ticketing (.NET) | Generates signed SVG QR code |
| `InvoiceAssetService.java` | Finance (Java) | Builds invoice PDF and uploads to MinIO |

## Storage Layout in MinIO

```
eventzen-invoices/
└── invoices/
    └── {year}/
        └── {paymentId}.pdf

eventzen-tickets/
└── tickets/
    └── {year}/
        └── {registrationId}.pdf
```

## Email Delivery

Both assets are emailed to the attendee:
- The **ticket pass** is attached to the booking confirmation email as an HTML-rendered PDF attachment
- The **invoice** PDF URL is included in the payment receipt email

If MinIO is unavailable (e.g. local dev without storage configured), `InvoiceAssetService.isEnabled()` returns `false` and generation is gracefully skipped - the payment is still recorded, just without a PDF.
