# 🪣 MinIO

**Role:** S3-Compatible Object Storage  
**Image:** `minio/minio:latest`  
**Category:** Advanced Infrastructure

---

## Overview

EventZen uses **MinIO** as a self-hosted, S3-compatible object storage layer. Rather than shipping binary files (ticket passes, invoice PDFs) as database BLOBs or serving them from the application container's filesystem, all generated assets are stored in MinIO buckets and served via pre-signed URLs - matching production-grade cloud storage patterns without a cloud vendor dependency.

---

## What Is Stored

| Asset | Service | Bucket |
|-------|---------|--------|
| QR Ticket Pass PDFs | Ticketing Service | `ticket-passes` |
| Invoice PDFs | Finance Service | `invoices` |
| Event cover images (if applicable) | Event Service | `event-assets` |

---

## Integration

### Ticketing Service (.NET)

- `TicketPassStorageService` uses the **AWSSDK.S3** client pointed at MinIO's endpoint
- After generating the ticket pass PDF, it uploads to the `ticket-passes` bucket
- Returns a pre-signed URL valid for a configurable duration for the frontend to download

### Finance Service (Java)

- `InvoiceAssetService` uses **Spring Cloud AWS S3** (or AWS SDK v2) configured with MinIO endpoint
- Invoice PDFs generated by a PDF library are streamed directly to MinIO
- Pre-signed URLs are returned to the attendee for download

---

## Why MinIO over Shared Volume

- **Pre-signed URLs** - files are served directly to the browser without proxying through the app service
- **Access control** - bucket policies and user credentials managed independently
- **S3 API compatibility** - swapping MinIO for AWS S3 in production requires only an endpoint/credentials change
- **Scalability** - decouples storage from compute; storage grows independently
